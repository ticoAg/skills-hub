# 诗词意境海报

先理解原文，再让形式服务诗意。默认直接完成一张成品；只有用户要求方案、提示词或预演时才停在相应阶段。保持两个模块，并用结构化的「语义画面规格」连接它们；不要把内部分析全部倾倒给用户。

## 输入与边界

- 接收原文、篇名、作者、用途、比例、风格、数量、参考图及可访问历史。默认一张、9:16、现代东方极简封面。
- 缺少诗词时索取原文，不把视觉示例误当诗文。只给篇名时核实版本；有歧义就请求原文。只给节选时不擅自补全。
- 以用户提供的原文为排版底稿。遇疑似错字或版本差异，指出疑点，不静默改字；篇名和作者不确定就省略，不编造署名。
- 区分明确硬约束与参考示例。用户锁定的巨大垂卷、米白女子、抚卷动作必须保留；仅是示例时不要给所有诗强加女子、卷轴、竹林、月亮或印章。
- 硬约束与诗意冲突时，先尝试明确的艺术隐喻；仍无法兼容就说明具体冲突并索取选择，不靠改季节、时辰或叙事来装饰画面。

## 模块一：内容理解

读取 [references/content-understanding.md](references/content-understanding.md)。按原文逐层提取，未明示项标为未知，保留合理歧义：

1. **对象与谓词**：谁／什么，在何处，做什么；主宾、否定、数量、方向、距离与因果关系。
2. **时空与进程**：季节、时辰、天气、地理尺度；先后事件、回忆与现实、静态与运动。
3. **观察者与视角**：谁在看、听、回忆或想象；诗人不自动等于画中人物，隐含主体不自动设为女子。
4. **情绪与转折**：主情绪、次情绪、节奏、关键转折及证据。不要把豪迈、惊喜、愁绪都读成“安静禅意”。
5. **感官与节奏**：声音、静默、冷暖、触感、密度、句式与重复。将声音转成动作、空间节奏或留白，不随意新增可见发声者。
6. **对照与修辞**：有／无、远／近、动／静、众／独；比喻、夸张、象征与典故。区分修辞与现实，不能把“千里”“万重”当物件数量。
7. **主题与留白**：用一句话写出最小完整诗意，提炼 2–4 个辨识锚点和不可破坏的核心关系，给新增细节设边界。

将文学理解转换为内部「语义画面规格」：

| 字段 | 内容 |
| --- | --- |
| evidence | 原文短句 → 解读；标记明示、推断、艺术隐喻，必要时注明不确定性 |
| thesis | 一句最小完整诗意，不泛化成“古风唯美” |
| anchors | 2–4 个必须保留的语义锚点，至少一个动作或物象关系 |
| scene_logic | 主体关系、空间方向、时间阶段、观看位置、叙事转折 |
| visual_translation | 每项视觉指令对应的证据与转译理由 |
| invariants | 不随版本变化的诗意、准确文字与用户硬约束 |
| variable_axes | 可改变的构图、视角、尺度、媒介、光线表达与文字区 |
| forbidden | 本诗特有的矛盾、无依据故事、泛古风装饰 |

不要求图像模型理解全部文学术语。把规格压缩为可画的主体、动作、相对位置、尺度、光线与明确禁项。删减次要意象可以，改变原文关系不可以。

## 模块二：视觉展示

### 设计与去重

读取 [references/visual-method.md](references/visual-method.md)。在内部拟定三种符合相同语义规格的构图，比较后只生成最终选择的方案，除非用户要求多张。候选必须改变观看方式与空间关系，不只改衣色或印章位置。

- 默认宣纸白、高明度、清透柔光、轻纸纹、清晰边缘和较大留白。依诗意调整冷暖、局部色彩与明暗；明示夜色时不能因高明度要求而画成白昼。朱砂点睛可选，最多一枚小印记。
- 用尺度和距离表现孤独，用斜线与连续岸影表现急行，用遮挡后的显露表现惊喜。不要堆齐所有名词，也不要为了变化删除核心物象。
- 为候选填七个稳定分类值：`layout / viewpoint / subject_relation / scale / medium / lighting / typography`。标签与记录格式见 [references/prompt-spec.md](references/prompt-spec.md)。复用已有同义标签，不能改措辞假装不同构图。
- 与当前对话作品、用户提供的历史图及当前授权项目记录比较，不检索其他对话或无关文件。
- 有 Python 与可写项目时，用 `scripts/poster_history.py` 管理成功作品。默认数据库为当前项目 `output/poetry-posters/history.sqlite3`，不写进安装目录或公共仓库。
- 对同诗最近三条和全项目最近二十条历史，逐条要求至少三个未锁定维度不同，且 `layout / viewpoint / subject_relation / scale` 至少一项不同。保持语义锚点和硬约束；`check` 失败则重构。
- 用户锁定过多维度时，保持约束并解释无法达到变化标准，不绕过检查。明确要求复刻或只改一个局部时按编辑执行，不承诺新构图，不新增原创去重记录。
- 无历史时仍比较本次候选。无脚本环境时手动检查；说明跨会话变化仅覆盖可见历史。分类检查只是启发式，最终必须目视比较，不保证永久绝对不重复。

### 文字与提示词

- 默认从原诗选最能代表主旨的一至两句，配篇名与已确认作者。用户指定文案或全文时遵守。保留原字、原顺序和原标点，只做视觉断行；自拟设计标题不得伪装成原句。
- 默认预留约 20–35% 标题区域、35–60% 视觉留白和 5–8% 四边安全边距；依诗意与版面调整，避免主体和文字重叠。
- 优先清楚的细宋／现代宋体与横排；需要竖排时明确从右到左的列顺序与从上到下的字序。避免难辨草书。
- 在提示词中逐字列出允许出现的文字及位置；禁止额外伪汉字、随机落款、水印。长卷默认空白，文字在留白处，除非用户要求写在卷上。
- 按 [references/prompt-spec.md](references/prompt-spec.md) 生成自足的提示词，写出具体画面；不要仅向模型提交诗文加“高级、诗意、唯美”。

### 出图与模型

读取 [references/model-routing.md](references/model-routing.md)，使用当前真实可用的图像工具；有 imagegen skill 时先遵守其规范。用户提出 `gpt-image-2.5` 时核对模型选择能力及官方标识，不虚构 model、size 等工具字段，不声称锁定无法选择的模型。

- 普通成品请求使用图像生成／编辑工具，内置模式不要求 API key。用户未要求 API／CLI 时不增加 SDK 或依赖安装；不以 SVG／HTML 代替生成式画面。
- 明确要求 9:16；工具有尺寸字段时选该模型支持的精确尺寸，没有则在提示词中指定并核验实际输出。
- 参考图只继承用户需要的风格，主体服从本诗；编辑目标先查看图像，再明确文字、构图与其他不变量。
- 用户只要提示词时，输出完整提示词与简短理由，不出图、不写成功历史。无图像工具时明确“尚未生成图像”。

### 看图验收

检查实际结果，不能只检查提示词：

1. 原文锚点和核心关系可见，时空、数量、动作及主情绪不矛盾；艺术补充没有抢走主旨。
2. 对比可访问的历史图，确认视角、尺度、主体关系与空间形态有变化，不能仅换色。
3. 逐字核对文字、标点、篇名、作者、阅读顺序、清晰度与边距。
4. 第一眼有主视觉与标题层级，留白可承载文字，结构清楚、轻纸纹、没有全图灰雾或无关道具。
5. 核验真实宽高比；有本地图时读取尺寸，否则用工具输出核验，并说明无法确认的项目。

发现问题就最小范围编辑，重复语义锚点与排版不变量。连续两次文字修正仍失败时，若用户未限制制作方法，用真实中文字体在生成底图上补排；用户不允许后期排字或工具不足时，说明具体未通过项，不能将错字当成成品。查看并核验最终图。

只有实际生成并通过检查的作品才可 `record`。分类记录要对应实际画面，偏离原方案时重新检查。失败、未生成、提示词预演与重复编辑均不登记成功历史。

按当前环境规范展示或保存成品，附一至两句原文映射与构图特点说明。仅在影响结果时交代模型、文字、比例或历史范围限制。

## 维护验证

修改后用 [references/evaluation-cases.md](references/evaluation-cases.md) 预演差异化诗词、同诗变化与失败场景；历史工具运行仓库根目录的 `python -m unittest discover -s tests -v`。预演通过不等于实际图像验收，不得声称未生成的图像已通过检查。
